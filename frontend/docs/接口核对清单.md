## 三、🔴 联调前必须解决

### A1｜`GET /users` —— §6 缺接口，前端已在用

- **§6 怎么写的** — §6.2 只有 9 条：登录、退出、`GET /users/me`、`PATCH /users/me`、改密码、`POST /users`、`PATCH /users/{id}`、重置密码、`/audit-logs`。**没有"列出用户"的接口。**
- **前端怎么做的** — `getUserListApi({ page, size, keyword, role })` `src/api/index.js:825`，注释即 `// GET /api/v1/users`；调用方 `src/views/admin/Users.vue:170`
- **影响** — 后台「用户管理」页需要列出用户才能操作，**联调时后端不会提供这个接口**
- **处置** — **补 §6**：加入 §6.2，作为第 10 条

### A2｜`GET /home/index-data` —— §6 缺接口，前端已在用

- **§6 怎么写的** — **全文无 `/home` 路径。** §6.2 ~ §6.7 覆盖账号、案例、AI、问答、管理后台五块，唯独没有首页
- **前端怎么做的** — `getHomeIndexApi()` `src/api/index.js:937`，注释即 `// GET /api/v1/home/index-data`；调用方 `src/views/Home.vue:129`；返回 `{ totalCases, collectedCaseCount, totalProfessions, totalTags, totalAiGenerated }`（`src/api/mockData.js:532`）
- **影响** — 首页是**所有登录用户**的第一屏，其数据接口在 §6 中完全缺失
- **处置** — **补 §6**：新增一节（如 §6.8 首页接口）

### A3｜「全部案例」的路径不一致

- **§6 怎么写的** — `#31 GET /admin/cases` — 全部案例查询（含各状态），管理员
- **前端怎么做的** — `src/views/admin/Review.vue:324` 调的是 `getCaseListApi({ page, size, includeAll: true })`；`getCaseListApi` 确为管理员开了口子（`src/api/index.js:178`），支持 `includeAll` 与 `status`
- **影响** — §6 定义的 `/admin/cases` **从未被调用**，管理员语义被塞进了公开接口 `/cases`。**联调必然接错。**
- **处置** — **二选一**：① 后端实现 `GET /admin/cases`，前端改调用；② 改 §6，承认 `GET /cases` 支持 `includeAll` / `status` 参数

## 四、🟡 需组内确认

### B1｜`DELETE /admin/cases/{id}` —— §6 缺接口，前端已实现

- **§6 怎么写的** — §6.7 相关三条为 `#31 GET /admin/cases`、`#32 PATCH /admin/cases/{id}`、`#33 POST /admin/cases/{id}/offline`，**中间没有 DELETE**
- **前端怎么做的** — `deleteCaseApi(id)` `src/api/index.js:715`，注释即 `// DELETE /api/v1/admin/cases/{id}`；调用方 `src/views/admin/Review.vue:406`
- **影响** — 前端多实现了一个 §6 未定义的接口；**联调时该请求无对应后端路由**
- **处置** — 确认是否需要该功能：需要则补 §6；不需要则移除前端删除按钮

### B2｜`DELETE /admin/tags/{id}` —— §6 只定义了 `PATCH`

- **§6 怎么写的** — `#37 /admin/tags/{id}` 为 **PATCH** — "编辑、**停用**思政标签"
- **前端怎么做的** — `deleteTagApi(id)` `src/api/index.js:816`，注释即 `// DELETE /api/v1/admin/tags/{id}`；调用方 `src/views/admin/Manage.vue:140`
- **影响** — §6 只给了 PATCH（停用），前端却用了 DELETE（销毁）。**HTTP 方法不一致，联调时 404。**
- **处置** — 确认是"停用"还是"删除"：若为停用，前端改用 `updateTagApi`（PATCH）；若确需删除，补进 §6

## 五、🔵 建议优化

### C1｜`/admin/tags`、`/admin/professions` 的查询路径与开放范围矛盾

- **§6 怎么写的** — `#36 /admin/tags` 与 `#38 /admin/professions` 的访问角色栏写"管理员（**查询可开放给师生**）"——路径在 `/admin/` 下，却标注对师生开放
- **前端怎么做的** — `getTagListApi()` `src/api/index.js:799`（注释即 `// GET /api/v1/admin/tags`）被 `src/views/CaseList.vue:200` 调用，用于**案例库筛选**
- **影响** — 案例库是**所有登录用户**可进的页面，学生实际会请求 `/admin/tags`。**路径语义（admin）与开放范围（师生）相矛盾**，后端做权限校验时容易出错
- **处置** — 建议拆开：公开的 `GET /tags`、`GET /professions`（登录即可），`/admin/` 下只保留增删改；并据此修改 §6
